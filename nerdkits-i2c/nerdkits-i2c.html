The NerdKits TWI/I²C Driver

An exercise in distributed embedded processing

Paul Duke — Originally developed March 2011

The NerdKits Days

Around 2011, I set out to learn the Atmel AVR family of microcontrollers. I didn't have a particular project in mind. My objective was simply to gain expertise with the chips and their capabilities.

I got started with NerdKits, which was also my first experience participating in an online discussion forum. Most of the guys there had some knowledge of electronics but relatively little experience in software development. I came from the opposite direction, with many years of professional software experience.

Before long, I was developing software components and sharing them with the group under the username Noter. It was a good exchange of knowledge, and I was having a lot of fun.

Intelligent Peripheral Devices

One of the things that interested me was the ability to develop my own intelligent I²C peripheral devices using inexpensive ATmega328 microcontrollers.

Rather than being limited to commercially available sensors and peripherals, I could program a microcontroller to perform whatever specialized function I needed and make it accessible through a standard I²C interface.

This provided a means of distributing processing responsibilities among several inexpensive microcontrollers.

Engineering for Performance

Performance was an important design consideration. I wanted the communications driver to be interrupt-driven so that the processors could continue doing useful work while communications were in progress.

The resulting driver incorporated several features:

  • Master and slave operation.
  • Nonblocking master transactions.
  • Optional application callbacks.
  • Application-supplied communications buffers.
  • Combined write/read transactions without releasing the bus.
  • Slave address masking.
  • General-call addressing.
  • Configurable communications bit rate.

The interrupt handler manages the communications protocol, leaving the application responsible for its own processing.

The Demonstration Programs

The original software includes a pair of demonstration programs running on separate AVR microcontrollers.

The master sends an integer to the slave. The slave increments the integer and returns the result during the read portion of the transaction. The master verifies the returned value and displays the results on an LCD.

Although simple, the demonstration illustrates the ability to distribute application processing between independent microcontrollers using a common communications interface.

Interestingly, several capabilities of my original 2011 driver are still not exposed by the standard Arduino AVR Wire interface as of November 2026.

The two drivers reflect different design objectives. Arduino emphasizes simplicity and ease of use, while my implementation emphasizes application flexibility and asynchronous operation.

Source Code Download

Presented here is the original version 1.2, dated March 18, 2011, preserved along with the demonstration programs and supporting libraries.

The software was developed in C using the AVR-GCC toolchain and AVR-LibC libraries, independently of the Arduino development environment. The archive includes the original Makefiles and device programming command files.

The archive includes:

  • TWI.c and TWI.h
  • Master and slave demonstration programs
  • Original Makefiles
  • Device programming command files
  • libNoter
  • libnerdkits

The software is preserved in its original form, including its historical build configuration.
